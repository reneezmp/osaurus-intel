Structural facts:
- Upstream's loop is a surface-agnostic driver (`run`) with surface hooks (`modelStep`, `executeBatch`, ...). Intel's engine runs the whole multi-round loop inside one `streamChat` and reports tool work to the UI with `StreamingToolHint`s. So every loop decision upstream makes in `run` has to be re-implemented inside the engine, and anything that needs a fresh model request (wrap-ups) has to be signalled back to `ChatSession.send`.
- Upstream chat policy is `stopOnToolRejection: true, wrapsUpIncompleteWork: true, budgetWarningThreshold: 0, todoStalenessThreshold: .max, maxDataMovementSteps: min(16, maxAttempts)`. HTTP/plugin: `stopOnToolRejection: false, dedupeNoticeEnabled: false`. So the budget warning and todo staleness notices are NOT used by upstream chat; Intel not having them is parity.
- Intel's terminal recovery (`terminalAction`) is gated on `ChatExecutionContext.interactiveChatRun` and `!isToolFreeWrapUp`: chat only. HTTP `/agents/{id}/run`, plugin inference and subagents get none of it from the engine.
- `classifyTerminal` is called without `content:` (CloudChatEngine L1362), so the announce-only and continuation-request classes can never fire.

Looks like user-visible bugs on Intel today:
1. **Denied tool re-prompts.** After a user Deny in chat the run continues; the model usually retries the same tool and the user is asked again (upstream ends the run with "The requested action was not completed."). Rows 9 and 18.
2. **Truncated tool call shows a raw error.** A model that hits Max Tokens inside a `file_write` produces `Error: ... exhausted its output limit while generating tool call ...` and the run dies; upstream retries once with a smaller-chunks notice. Row 10.
3. **Insights undercounts multi-round runs.** Input / output tokens on the single run row are the last round's, not the sum (`CloudChatEngine` L1932-1933 vs `runUsage`). Cost in Insights is therefore low for tool-heavy chats. Row 37.
4. **Partial reply replaced by the error.** A stream that fails after text has streamed (network drop, 5xx mid-stream) has that text overwritten by `Error: ...` (`ChatView` L4417); upstream appends. Row 15.
5. **Possible Stop artefact.** The outer `catch` has no `CancellationError` branch; the engine throws `CancellationError` on Stop. It is probably masked by the per-delta `isRunActive` check and the cancelled-marker code (L2891), but a Stop that lands between deltas may write an error line. Needs a Rosy check or a unit test.
6. **No out-of-credits message for the Router.** A 402 prints the raw `Router API error 402: {...INSUFFICIENT_FUNDS...}`; upstream shows "You're out of credits. Add credits to continue." and offers a retry after top-up. Rows 13-14.
7. **Weak-model stalls.** A model that announces a call and stops ("Let me write the file:") or asks "Would you like me to continue?" with a todo open ends the turn on that text (#2480; recorded in 3c-1). Rows 5-7.
8. **API and plugin runs never recover from an empty turn** (end with no output) and send the whole history untrimmed. Rows 40-41.

Already correct, no work: grounded-claim guards, todo scope, dedupe replay, run-ending tools, iteration-cap wrap-up, mid-run steer, usage hint, Router summary frames, tool scope gate (#2018), context trim in chat, manual-only compaction (deliberate).
