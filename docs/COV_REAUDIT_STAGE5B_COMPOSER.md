# Stage 5b: prompt composer behaviour audit (Intel vs upstream/classic 0.25.x)

Upstream: `Packages/OsaurusCore/Services/Chat/SystemPromptComposer.swift` (4138 lines), `ComposeRequest.swift`, `PromptManifest.swift`, `PromptBuilder.swift`, `SystemPromptTemplates.swift` (2032 lines), `ContextSizeClass.swift`.
Intel: `composeChatContext` in `Models/Chat/IntelConformers/IntelDataConformers.swift` (~L2677-3100, the class `SystemPromptComposer`), `Services/Chat/IntelPromptDiscipline.swift`, `Services/Agent/IntelOrchestratorPrompt.swift`, `Tools/CapabilityTools.swift:CapabilityManifest`. Intel's `SystemPromptTemplates.swift` (994 lines) is a stale snapshot of upstream's (no leanFolderContext, bulkEditGuidance, knowledgeGuidance, spawnGuidance, selfImprovement, secretHandling; old manifest renderer, unused on Intel).

Key structural fact: upstream's `appendGatedSections` has TWO paths. Any custom agent (or any agent with a folder or sandbox) takes the LEAN path (#2250) and returns early: it gets only platform, persona, soul, working directory, enabledManifest(+skillsGovern), pluginCreator and dynamic sections. The rich sections (family guidance, grounding, code style, risk-aware, agent loop, apple apps, knowledge, spawn, capability nudge) only render for the Default agent with no folder/sandbox. Intel is on the pre-lean full path for every agent (row 4).

## Notes (UNSURE)

- Row 4 is a product decision: dropping family guidance/grounding/code style/risk/agent-loop for custom agents removes behaviour Intel users have today (and the family nudges were added for DeepSeek-style tool-calling weakness). Rule "follow upstream by default" says port; Renée should confirm, and Rosy should retest tool calling on weaker cloud models after. Slice 6 can be done as a section-gating flag.
- Row 17: Intel's "Tool Use (MANDATORY)" folder directive is Intel-only; upstream's lean folder context drops the verbose dispatch guide. Keeping the directive on top of the lean text is the safer adaptation.
- Row 24: plugin instructions may be appended twice for a plugin-dispatched chat (composer by active tool + ChatView resolver). Not verified at runtime.
- Row 20: whether Intel `CapabilityCatalog.SkillItem` carries a plugin id (needed for per-group skills and `skillsGovern`) was not checked.
- Row 7: agentDB schema in the `[Memory]` prefix is frozen onto the turn it was sent with, so earlier turns carry stale schema snapshots (upstream re-renders it each turn in the system prompt). Harmless for correctness; slightly different cache behaviour.
- Whether Intel's Anthropic path sets `cache_control` (field exists in `Models/API/AnthropicAPI.swift:33`) was not checked; it affects how much rows 35-36 are worth.
- COV_REAUDIT.md's "no Capability Discovery section" should be corrected: `CapabilityManifest.discoveryGuidance` exists (row 18).
- `CapabilityClaimsEvaluator` (compiled on Intel) calls `composeChatContext`; any signature change in slice 5/6 must keep it building.
