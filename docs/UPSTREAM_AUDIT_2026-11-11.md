## The three structural facts (read these first)

1. **Intel's theme API is the old flat one; 1.0 replaced it.** Intel's `ThemeProtocol` has `primaryText`, `cardBackground`, `accentColor`... (about 2,070 uses in 202 files). 1.0's is role-based (`theme.text.primary`, `theme.surface.canvas`, `theme.action.*`, `theme.typography`, `theme.radius`, `theme.space`, `theme.motion`, `theme.effects`; about 1,470 uses in 318 files). `ThemeRoles.swift`, `ThemeTokens.swift`, `FixedPalette.swift` are new; `CustomTheme` is rewritten as "schema 7 seed documents, not user-editable"; `Theme.swift` shrinks 1,150 → 793 lines. A port is not a file swap: it is a codebase-wide rename plus every view that touches colour.
2. **1.0 removes user themes.** Deleted: `ThemesView`, `ThemeEditorView`, `ShareThemeSheet`, `ImportThemeByIdSheet`, `ThemePreviewImageCache`, `ThemeConfigurationStore`, `ThemeJSONEditorCodec`, `SystemAccentColor`. `ThemeManager` keeps only `appearanceMode` (System/Light/Dark), font zoom, and a one-time migration (`migrateRetiredActiveTheme` / `retiredThemeAppearance`: a custom theme maps to Light or Dark by its `isDark` flag). The look comes from a bundled design library (`LibraryResources/design-library.json`, `semantic-tokens.json`, `primitive-colors.json`, `component-mappings.json`) loaded by `DesignLibraryRuntime`. Intel has the whole theme library (editor, sharing, import-by-id, follow-system-accent, `docs/THEMES.md`). Following upstream means deleting a feature Intel shipped. That is a product decision for Renée, not a technical block.
3. **Min macOS is 15 and the new views use macOS 14/15 APIs freely** (see row 3). Intel already has `Views/Common/OnChangeWithPrevious.swift` (shim for the two-parameter `onChange`), and 1.0's area-C views use the two-parameter form about 419 times in `Views/` (Intel: 23 hits, most unrelated closures). Every one of those needs the shim.
