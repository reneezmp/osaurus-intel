Structural facts (checked in code):
- Intel builds an OpenAI chat-completions dictionary and translates at the edges (Anthropic, Gemini, Responses). The compiled `OpenAICompatibleStreamFramer` (`OpenAICompatibleStreamParser.swift`, 231 lines) is not called by the engine; `CloudChatEngine` parses lines itself (L2366-2489). `RemoteToolDetection`, `InlineThinkSplitter`, `RemoteImagePayloadPolicy.prepared` (Intel keeps only the size helpers) and `RemoteResponsesCapabilityFallback` are unused or absent.
- Intel's chat `URLSession` is `.shared` (init default, L317); upstream builds a per-provider session with `GlobalProxySettings` and `max(provider.timeout, 300)`.
- Intel's `RemoteProviderManager` is a stub class: `connect` = one `refreshModels`, `disconnect` is empty (L845), `findService` returns nil (L852).
- No money-losing double-bill path found in `streamChat` (Router `idempotency_key` is sent, 5c row 38). The money items are below: usage that is never recorded, retries after swallowed errors, one-shots that skip the Router summary frame.
- No data-loss path found. The one security item is custom header values reaching `URLRequest` unfiltered (row 33).
